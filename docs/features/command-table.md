# Command Table

Status: Built. PRD: [PRD.md](../PRD.md). Spec: [TECH_SPEC.md](../TECH_SPEC.md) sections 10.5 and 11. Related: [review-actions.md](review-actions.md), [toolbar-pager-footer.md](toolbar-pager-footer.md), [sidebar-shell.md](sidebar-shell.md), [poller.md](poller.md), [ticket-linking.md](ticket-linking.md), [stacked-prs.md](stacked-prs.md), [theme.md](theme.md).

## Purpose

The dashboard at `/`: one glass card per open pull request assigned to the user, opened by the user or waiting on the user's review, with its review,
CI, Jira and merge controls, the merge dialog, a note per pull request, the History view that replaces the list, and the left sidebar with the Settings content ([sidebar-shell.md](sidebar-shell.md)).

Differences from the spec:

- The Merge cell shows why a PR cannot be merged as a tooltip on a disabled Merge button, computed in the browser from the snapshot (`blockOf`, including "Needs N approvals, has M" from `SnapshotPr.approvals`). The reasons include "Read-only here: <token name> can't write to <owner/repo>" (when `SnapshotRepo.tokenName` is present, else "Read-only here: your token's account can't write to <owner/repo>") for a repository where the account's role is read or triage (`SnapshotRepo.viewerPermission`); Ready of a draft is disabled the same way unless the viewer opened it (`readyBlockOf`). The Blocked tile counts such a pull request, as `listStats` and the filters read `blockOf` too. The server checks the same things again when merging ([merge-and-transition.md](merge-and-transition.md)). The review actions (approve, request changes, ready) and the approvals counts are in [review-actions.md](review-actions.md).
- There is no full-width top bar. Two floating pills ([header.md](header.md)) hold the burger that toggles the left sidebar with Settings ([sidebar-shell.md](sidebar-shell.md)), the search ([search.md](search.md)), Refresh and the theme circle. The source status moved into the popover of Refresh.
- The list is cards, not a table. Each card has the avatar, the title, a meta line (repository and number, author, the age of the last update and of the last commit), the Jira row with the size of the change (+added, -removed), and a controls row (Hide, Review, CI, Merge) with dividers, drawn as in the design (see "The controls row" below). The per-pull-request merge method is no longer a column: it is chosen in the merge dialog ([merge-method.md](merge-method.md)).
- The stat strip is seven tiles: Showing, Ready to merge, Running CI, Blocked, Draft, Stale and Stacks. They count what the Show, hidden and search switches leave, and each tile is a button that filters the list to its pull requests ("Showing" lifts the filter). Ready, Blocked and Draft split the list by `blockOf`; Running CI (`ci.state` running) and Stale (last commit older than three days) cut across them; Stacks counts stacks, not their pull requests. Only the number of the Blocked tile is red (`--blocked-fg`, `#b3202c` in light mode, `#ff9aa2` in dark mode); its box and its label are those of the other tiles, at rest, on hover and while `aria-pressed` is true. The tile is a translucent glass tile, so the ratios are against the colours measured in the browser (rest, then hover `oklch(var(--bc) / 0.04)` and pressed `oklch(var(--bc) / 0.08)` over it). Light: number `#b3202c` on rest `#f8fbff`, hover `#f0f4f9` and pressed `#e9edf3` is 6.40, 6.02 and 5.66 to 1. Dark: number `#ff9aa2` on rest `#262d44`, hover `#2c334a` and pressed `#333a4f` is 6.75, 6.19 and 5.59 to 1. The compact line's Blocked button in the header pill has the same red number on the same hover and pressed fills as its siblings. The red is the `red` flag of the tile in `TILES`, drawn by the `statBlocked` and `csBlocked` classes, which only colour the number. The strip wraps onto more rows when it is narrow (tiles of at least 9.5rem that share each row), so it never makes the page scroll sideways. Once the strip has scrolled out of view the same tiles, as buttons with the same filters, show in a compact line in the right header pill ([header.md](header.md)). The old status chips are gone; a PR's block reason still shows on its Merge button. The sort, "Show" and "Hidden PRs" toolbar and the legend sit under the strip. Cards can be hidden, the list is paged at the bottom, and a footer with a GitHub button ends the page. All of it is client-side over the snapshot and is described in [toolbar-pager-footer.md](toolbar-pager-footer.md).
- Cards are tinted whole by why the PR is listed (`SnapshotPr.roles`): cyan-teal for a PR assigned to the user or opened by the user, red for one the user is only asked to review, split 46/54 (cyan-teal and red) when it is a review request and also assigned or opened by the user. A stack is one group with a purple left border and a banner ([stacked-prs.md](stacked-prs.md)). See the rules below.
- "Manage accounts", at the bottom of the sidebar, opens the Accounts dialog ([auth.md](auth.md)). The Accounts page (`/accounts/`) stays for OAuth returns.
- The history circle of the header swaps the stat strip, the toolbar and the list for the History view ([history.md](history.md)). A square button on each card opens a note kept in the browser ([notes.md](notes.md)). Repositories switched off in the sidebar are left out of the list, the stat tiles and the toolbar counts ([settings.md](settings.md)).

## Data model

Reads `Snapshot` from `GET /api/snapshot` ([poller.md](poller.md)), which gives each PR its `author`, `updatedAt`, `additions` and `deletions` (all nullable) for the card and `Settings.theme` (applied by `useTheme`; the theme is changed with the header button, [theme.md](theme.md)). Writes, through the ticket cell, `TicketLinks`. The merge dialog reads `SnapshotPr.mergeMethod` ([merge-method.md](merge-method.md)) and calls the merge API ([merge-and-transition.md](merge-and-transition.md)); the Review cell calls the review API ([review-actions.md](review-actions.md)). Filter (a stat tile), sort, page, the open dialog or menu, the chosen method and the open dialogs are component state only; the hidden pull requests, the hide mode and the page size are in `localStorage` ([toolbar-pager-footer.md](toolbar-pager-footer.md)); the outcome of merges made in the tab (with the pull request as it was) is in the query cache under `merges`, which feeds the History view; notes are in `localStorage` ([notes.md](notes.md)).

## Key flows

1. `/` loads the session, then `getSnapshot` (sends `If-None-Match`, reuses the cached copy on `304`).
2. `useSnapshotEvents` opens `/events`. A `snapshot` event invalidates the query, a `sync-status` event is stored for the header.
3. `List` selects groups of ids from the snapshot (filter, Show and search, stacks in order, then sorted and with hidden pull requests applied) and shows the current page of them. TanStack Query's structural sharing keeps the result equal when no id or grouping changed, so only changed cards re-render: each `Card` selects its own PR.
4. The Merge button of a ready card opens the merge dialog ([merge-and-transition.md](merge-and-transition.md)), which holds the method (with its source and the fallback warning), the delete-branch choice and the ticket moves. A merge the server accepts plays the launch on the card, then the card leaves and a toast sums it up.
5. Refresh (the circle in the header) calls `POST /api/sync`. It spins and ignores clicks while the status says running, and a toast says what the refresh found ([header.md](header.md)).
6. The CI badge shows the rollup ("Passing", "Fails", "Running" with a spinner, "No CI"). Its italic "i" segment opens the checks popover.

7. The controls row, from the left. Four cells separated by 1px dividers: Hide, Review, CI and Merge (grid `6.4rem 6.4rem 7.3rem 6.1rem` with the dividers between; the first cell holds the note button and the Hide checkbox). Everything is in [Controls.module.css](../../web/src/components/CommandTable/Controls.module.css), on the design's tokens, light and dark.

   - Review: the "Action" menu or a state badge ([review-actions.md](review-actions.md)). A 6.1 rem by 1.75 rem pill with a 1px border.
   - CI (`CiCell`): a 7.1 rem outlined badge, green "Passing", red "Fails", amber "Running" (a 1 rem spinner, still under reduced motion) or the ghost "No CI". The italic serif "i" after a 1px separator is a button (`aria-label` "Checks for #N", `aria-haspopup="dialog"`) that opens a 16 rem popover in a portal, placed under the badge (above when there is no room) and lined up with its right edge (`usePopover`, gap 6). The popover is a `role="dialog"` named "Checks for <owner/repo> #N" with the same title, one row per check (a state dot, the name, "passed", "failed", "running", "queued", "skipped", "neutral" or "cancelled"), "+N more" when GitHub reports more checks than the list holds, a note when only the count is known ("N checks, their names are not available") or there are none ("No checks reported"), and the link "Open all checks on GitHub ↗" to the pull request's checks page (`githubChecksUrl`, https only, `rel="noopener noreferrer"`). It takes the focus, closes with Escape (the focus goes back to the "i"), Tab, a click outside or the "i" again, and follows the page while it scrolls. The per-check run links of the old list are gone: the design's rows are not links.
   - Jira (`TicketCell`, in the card body): ticket badges and the "My tickets" menu ([ticket-linking.md](ticket-linking.md)).
   - Merge (`MergeCell`): the blue aura button, a disabled Merge with a tooltip on its left, or the green Mark ready button of a draft ([merge-and-transition.md](merge-and-transition.md), [review-actions.md](review-actions.md)).
   - Tooltips are `Tip`: the design's dark bubble from `data-tip`, on hover and on keyboard focus. A control that has one also has the same text as its accessible description, so nothing depends on hovering.
   - Disabled looks: the shared default disabled button (20% fill and text, the "no" cursor) for a blocked Merge, which is `aria-disabled` and not `disabled` so a keyboard user can reach it and hear the reason.

## Outside calls

None from the browser to a provider. It calls only `/api/*` and `/events` on its own origin.

## Rules and invariants

- An enabled Merge button is the design's blue (`--merge` in [globals.css](../../web/src/app/globals.css), `#0066cc`, 5.6:1 with the white text; hover `--merge-hover` `#0a70d8`, 4.9:1) with white text, the merge mark, radius .5rem, height 32px, and an aura that pulses for 2.6s (`aura` keyframes in `CommandTable.module.css`, off under `prefers-reduced-motion`). Hover is `--merge-hover`, a press scales to 0.95, the cursor is `merge.svg`. A disabled Merge button has the shared disabled look (20% fill and text), the "no" cursor, no aura and no press scale. See [theme.md](theme.md).
- The Merge button is enabled only for a ready row. The dialog never sends a head SHA other than the one the card had when the dialog opened.
- A card is a flex row from 1024px (the body takes the rest, the controls row has fixed columns with 1px dividers) and a column below it, so the controls stack under the title at 390px. Padding 16px, radius 1.1rem, gap 16px between cards. There is no hover state on a card.
- Links come from `safeLink` or the URL builders: https only, no credentials, github.com links rebuilt from the path alone, external hosts shown as host text, `target="_blank"` with `rel="noopener noreferrer"`. The Authorize link is built from a validated organization name (`https://github.com/orgs/<org>/sso`), never from a server URL.
- No inline styles (CSS Modules and custom properties), no `dangerouslySetInnerHTML`. `pnpm -C web build` writes the CSP hashes and must pass.
- Times are relative with the absolute time as tooltip. Animations stop under `prefers-reduced-motion`.
- Role cue: `Card` adds `role_assigned` (assigned and/or opened by the user, the green tint), `role_reviewer` (review requested only, the red tint) or `role_both` (review requested and assigned or opened, the 46/54 split) (from `roleKind`) to the card. The classes set the whole card's background and border from the `--card-a-*`, `--card-r-*` and `--card-b-*` tokens in globals.css: 28% of the design's `--rc-a` or `--rc-r` over the surface in light mode, the translucent teal and pink gradients of the design in dark mode, and a 46/54 split for both. Classes only, no `style` attribute. Muted text uses `--sub` (85% in light, 80% in dark) rather than the design's 70% and 60% opacity, so that it keeps 4.5:1 against every tint. Dimmed hidden cards keep their intentionally lower opacity.
- Hiding: in All mode a hidden card is at 50% opacity. A card that leaves the list plays `ghostOut` (.48s, fades, blurs, turns grey and moves up 16px) and is removed when it ends; one that stays plays `ghostDim` or `ghostIn` once (.5s). Under `prefers-reduced-motion` the change is applied at once.
- Ready, blocked and draft come from `blockOf`. Running CI is `ci.state === 'running'`.
- Per-check states: passing, failing, running, pending, skipped, neutral, cancelled.
- Popovers, menus and dialogs are rendered at the end of the body (a glass card is a containing block for fixed children and would misplace them) and never use a `style` attribute in markup: `usePopover` sets the position on the element from the script, as the other popovers do.
- A merged card stays in the list while its launch plays, even when the snapshot already dropped it (`pinLaunched`); it never delays the request ([merge-and-transition.md](merge-and-transition.md)).
- The empty list says what emptied it (`EmptyState` in `List.tsx`, one `Notice` each, read from `sources.github.state` and the number of pull requests in the snapshot): GitHub not connected and no pull request ("GitHub is not connected" with a "Connect GitHub" button that opens the Accounts dialog, as the sidebar's Manage accounts does); no pull request at all ("No open pull requests"); a search with no match ("No matches" with "Clear search"); otherwise the Show, filter, repository and hide switches ("Nothing here, No open pull requests match these switches and filters." with "Reset filters", which sets the tile filter and Show back to All, switches every repository on and shows hidden cards too when some are hidden). The blocked-organization banner and the disconnected notice above the list are unchanged.
- Render cost. Every selector given to `useSnapshot` is stable (module level or `useCallback` on its inputs) and its result is structurally shared by TanStack Query, so an identical snapshot, or a keystroke that leaves the same numbers, renders nothing again. `useListPrefs` returns one memoized object with setters that never change. `SidebarPane`, `Header`, its buttons, `Toolbar`, `Footer`, `OrgBanner`, `StatStrip`, `CompactStats`, `StackBanner`, `List` and `Card` are memoized. `List` keeps what its callbacks read (hidden set, running motions, mode, groups) in a ref, so `onHide` and `onMerged` are the same functions render after render and hiding one card renders that card only. `prsById` builds the id map once per snapshot (a `WeakMap`), for the sort, the stats, the stack banner and `useSnapshotPr`. `groupsOf` orders its groups with a precomputed index of the snapshot, not a search per comparison.
- The Accounts dialog, the rules dialog and the History view are separate chunks (`React.lazy` with `Suspense`, loaded when first opened; the History code is also fetched 1.5 s after the page is drawn, so the first toggle fades into a finished view) and so is the merge dialog (loaded when a Merge is first clicked).
- One `EventSource` serves all the tabs of the browser. `useSnapshotEvents` asks for the Web Lock `prdash-events`; the tab that gets it opens `/events`, applies each `snapshot`, `activity` and `sync-status` event and rebroadcasts it on the `BroadcastChannel` `prdash-events`; the other tabs wait in the lock queue and apply the same cache update from the channel (snapshot and activity refetch from the server, which makes no outside call; a sync status is stored). A tab that joins posts `hello` and the leader answers with its last sync status, because the server replays its last events only to a new stream. When the leader's tab closes the lock is released, the next tab opens the stream and the server's replay brings it up to date. Without `navigator.locks` or `BroadcastChannel` each tab opens its own `EventSource`. Messages are validated before they are applied.
- Mutations invalidate only the queries they change (`useAction` takes the list): account and token changes refresh the accounts, the settings, the snapshot, the repositories and the Jira lists; saving a client refreshes the setup and the accounts; saving settings refreshes the settings, accounts (the selected Jira site), repositories, snapshot, assigned tickets and the activity log; revoking sessions refreshes nothing. None of them touches the sync status, which has no fetcher and is fed by the event stream.
